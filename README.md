# Support Inbox тестовое задание
https://github.com/Wockeez/interview-tasks/tree/master/senior-1#readme

Инбокс оператора поддержки. Слева список обращений, справа переписка. Можно искать, фильтровать по статусу, открыть обращение, сменить статус и ответить. Выбранное обращение и фильтры живут в URL, поэтому прямая ссылка, «назад» и «вперёд» работают сами.

Бэкенд: `https://evo-academy.wckz.dev/api/senior-1`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/tickets?query=&status=` | список |
| GET | `/tickets/:id` | обращение и сообщения |
| PATCH | `/tickets/:id/status` | смена статуса |
| POST | `/tickets/:id/replies` | ответ оператора |

## Как устроено

Angular 21, standalone-компоненты, signals, zoneless (`provideZonelessChangeDetection`). Zone.js здесь не нужен: всё, от чего должен перерисоваться экран, уже сидит в сигналах. У компонентов всё равно стоит `OnPush` — zoneless это не отменяет, а явный режим проще читать, чем дефолт.

Состояние разбито на три стора `@ngrx/signals`, а не свалено в один.

- `TicketsStore` содержит только список. Тикеты лежат в `withEntities`, фильтры он не хранит сам, а читает из URL.
- `TicketDetailStore` живёт на роуте `:ticketId`. Ушёл с карточки — стор уничтожился вместе с роутом, старое обращение не остаётся в памяти. Туда же сложены загрузка детали, ошибка ответа и флаг «ответ сейчас отправляется». Черновик текста остаётся в компоненте: это содержимое textarea, а не результат запроса.
- `TicketStatusStore` отдельно, потому что статус можно менять и из списка, и из карточки, и запросы по разным обращениям не должны затирать друг друга. Для каждого id хранится, идёт ли обновление и какая была ошибка.

Фильтры синхронизирует `TicketsUrlSync`. Поиск и статус пишутся в query (`q`, `status`), id обращения — в path. Стор подписывается на сигнал фильтров в `onInit` и грузит список через `rxMethod` + `switchMap`: быстрая смена фильтра отменяет предыдущий запрос, а не дорисовывает устаревший ответ. Поиск дебаунсится в `TicketSearchBar` (300 мс). Черновик строки — `linkedSignal` от текущего query, чтобы поле не разъезжалось с адресной строкой, когда фильтр меняется снаружи.

`ticketId` в деталь приходит как `input()` через `withComponentInputBinding`. Компонент не читает `ActivatedRoute`.

Ответы API проверяются zod прямо в `TicketsApiService`. Наружу уходят уже нормальные типы, а не `unknown`. HTTP-ошибки перехватывает один interceptor и складывает их в `ApiError` (сеть, http, валидация). Сторы разбирают только его: отдельный текст для 404 («обращение не найдено»), остальное — сообщение с бэка или запасная фраза.

Даты с бэка приходят без пояса и с пробелом вместо `T`, например `2026-09-28 12:30:28.612`. `new Date` читает такую строку как локальное время, и «5 минут назад» превращалось в «4 часа назад». Парсинг вынесен в `DateParser`: naive-строка дополняется до UTC, всё остальное работает уже с `Date`. Относительная подпись считается в `relativeTime`, абсолютная — через `formatDate` и смещение из `UserTimeZone`. Если формат бэка изменится, правится парсер, а не каждый компонент с датой.

«N минут назад» обновляет один `TickerService` на всё приложение, раз в минуту. У каждого `TimeAgo` нет своего таймера.

Клавиатурное поведение вынесено в директивы и навешано на host, а не размазано по компонентам: активация строки списка (`Enter` / `Space`), стрелки по списку, клик снаружи и `Escape` для меню статуса.

Список и деталь в шаблоне не ветвятся по сырому статусу запроса. Компонент заранее собирает view (`loading` / `error` / `empty` / `ready`, у списка ещё `stale` — ошибка обновления при уже показанных карточках), шаблон только переключает её.

Стили — обычный SCSS, без UI-кита.



## Запуск

```bash
npm install
ng serve
```

Приложение откроется на `http://localhost:4200/`.

```bash
ng test
ng build
```
